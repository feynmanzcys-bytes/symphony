## Установка

Быстрее всего так: откройте Claude Code и вставьте

> Установи мне https://github.com/feynmanzcys-bytes/symphony

Claude Code прочитает этот README и сделает всё, что описано в следующем разделе. Чтобы установить вручную, выполните те же шаги.

### Для AI-агентов: инструкция по установке

Вы читаете это, потому что пользователь попросил вас установить symphony. Выполните шаги ниже по порядку, в оболочке, и закончите отчётом из шага 6. Ничего не спрашивайте у пользователя, если шаг этого не требует; обычные решения принимайте сами и перечислите их в отчёте.

У symphony две части, и нужны обе:

1. **Программа `symphony`** (bridge): один исполняемый файл, локальный веб-сервер на `http://127.0.0.1:7788/`, который отдаёт страницу офиса и запускает сеансы. Она должна лежать в `PATH` пользователя под именем `symphony`, потому что mod запускает её командой `symphony -background`, когда сеанс не находит работающий bridge.
2. **Плагин `symphony-bridge`** (mod): плагин Claude Code из маркетплейса этого репозитория, установленный на уровне пользователя. Он действует только в сеансах, запущенных с `SYMPHONY_TOKEN`, и ничего не делает во всех остальных.

#### Шаг 1: проверьте машину

```bash
uname -sm                 # Linux/macOS: по нему выбирается архив ниже (x86_64 → amd64; arm64/aarch64 → arm64)
claude --version          # нужен Claude Code 2.1.x (проверено на 2.1.316)
git --version             # только для совместных задач; если его нет, отметьте это в отчёте, но не останавливайтесь
symphony -version         # уже установлен? выводит "symphony v0.7.1 (darwin/arm64)"
curl -s http://127.0.0.1:7788/api/state | head -c 40   # bridge уже работает? выводит {"type":"snapshot",...
claude plugin list --json # mod уже установлен? ищите "id":"symphony-bridge@symphony"
```

В Windows используйте PowerShell: `$env:PROCESSOR_ARCHITECTURE` равно `AMD64` или `ARM64`, а вместо curl — `Invoke-WebRequest http://127.0.0.1:7788/api/state`.

Если `claude` нет, остановитесь и скажите пользователю сначала установить Claude Code. Если и программа, и mod уже на месте, переходите к разделу «Обновление» ниже.

#### Шаг 2: получите программу

Возьмите первый вариант, который сработает:

- **A. Через `gh`** (работает, пока репозиторий приватный, если `gh auth status` показывает выполненный вход):
  ```bash
  gh release download -R feynmanzcys-bytes/symphony --pattern 'symphony_<os>_<arch>.tar.gz' -D /tmp/symphony-dl
  ```
- **B. Через `curl`** (только когда репозиторий станет публичным; 404 означает, что нужен A или C):
  ```bash
  curl -fL -o /tmp/symphony-dl/symphony_<os>_<arch>.tar.gz https://github.com/feynmanzcys-bytes/symphony/releases/latest/download/symphony_<os>_<arch>.tar.gz
  ```
- **C. Из исходников** (Go 1.27 или новее; клон пригодится ещё в шаге 4):
  ```bash
  git clone https://github.com/feynmanzcys-bytes/symphony.git /tmp/symphony-src
  cd /tmp/symphony-src && go build -o symphony ./cmd/bridge
  ```
  Соберите исполняемый файл; `go run` не подойдёт, потому что `-autostart` отказывается работать со сборкой через `go run`.

| Система | x86-64 | ARM64 |
| --- | --- | --- |
| Linux | [`symphony_linux_amd64.tar.gz`](https://github.com/feynmanzcys-bytes/symphony/releases/latest/download/symphony_linux_amd64.tar.gz) | [`symphony_linux_arm64.tar.gz`](https://github.com/feynmanzcys-bytes/symphony/releases/latest/download/symphony_linux_arm64.tar.gz) |
| macOS | [`symphony_darwin_amd64.tar.gz`](https://github.com/feynmanzcys-bytes/symphony/releases/latest/download/symphony_darwin_amd64.tar.gz) (Intel) | [`symphony_darwin_arm64.tar.gz`](https://github.com/feynmanzcys-bytes/symphony/releases/latest/download/symphony_darwin_arm64.tar.gz) (Apple silicon) |
| Windows | [`symphony_windows_amd64.zip`](https://github.com/feynmanzcys-bytes/symphony/releases/latest/download/symphony_windows_amd64.zip) | [`symphony_windows_arm64.zip`](https://github.com/feynmanzcys-bytes/symphony/releases/latest/download/symphony_windows_arm64.zip) |

В каждом архиве лежат программа (`symphony`, в Windows — `symphony.exe`), `LICENSE` и `README.md`. В `checksums.txt` релиза есть SHA-256 каждого архива (`sha256sum -c --ignore-missing checksums.txt`, в macOS — `shasum -a 256 -c`).

#### Шаг 3: добавьте её в PATH

Выберите папку, которая уже есть в `PATH` пользователя и доступна для записи без `sudo`: `~/.local/bin`, `/usr/local/bin` или `/opt/homebrew/bin`, именно в таком порядке. Если ни одной из них нет, создайте `~/.local/bin`, добавьте её в rc-файл оболочки (`~/.zshrc` или `~/.bashrc`) и упомяните это в отчёте.

```bash
tar xzf /tmp/symphony-dl/symphony_<os>_<arch>.tar.gz -C /tmp/symphony-dl
install -m 755 /tmp/symphony-dl/symphony ~/.local/bin/symphony
xattr -d com.apple.quarantine ~/.local/bin/symphony 2>/dev/null || true   # macOS: исполняемый файл не подписан
symphony -version          # выводит "symphony v0.7.1 (linux/amd64)": версию и платформу
```

В Windows: `Expand-Archive symphony_windows_<arch>.zip -DestinationPath "$env:LOCALAPPDATA\Programs\symphony"`, затем добавьте эту папку в `Path` пользователя (`[Environment]::SetEnvironmentVariable('Path', "$([Environment]::GetEnvironmentVariable('Path','User'));$env:LOCALAPPDATA\Programs\symphony", 'User')`) и откройте новую оболочку. При первом запуске SmartScreen может предупредить: нажмите «Подробнее», затем «Выполнить в любом случае».

Если ваша собственная оболочка после этого не находит `symphony` (её `PATH` был прочитан до изменения), в остальных шагах указывайте абсолютный путь.

#### Шаг 4: установите mod

```bash
claude plugin install symphony-bridge --marketplace feynmanzcys-bytes/symphony
```

Эта команда добавляет репозиторий как маркетплейс плагинов `symphony` и устанавливает mod на уровне пользователя, без вопросов. Она клонирует репозиторий через git, поэтому, пока репозиторий приватный, нужен git-доступ к GitHub. Если установка не удалась по этой причине, возьмите в качестве маркетплейса клон (из шага 2 C или сделайте новый): `claude plugin install symphony-bridge --marketplace /absolute/path/to/symphony`. Когда маркетплейс — это клон, сеансы читают mod из этой папки, а `git pull` в ней его обновляет.

Проверьте:

```bash
claude plugin list --json   # у одной из записей "id":"symphony-bridge@symphony", "scope":"user", "enabled":true
```

- `"scope":"project"` или `"local"`: mod будет загружаться только в одной папке. Выполните `claude plugin uninstall symphony-bridge@symphony`, затем установите заново с `--scope user`.
- `"enabled":false`: выполните `claude plugin enable symphony-bridge@symphony`.

#### Шаг 5: запустите bridge

```bash
symphony -autostart on -open=false
```

Эта команда запускает bridge сейчас и при каждом входе в систему (пользовательская служба systemd в Linux, агент launchd в macOS, раздел реестра Run в Windows) и выводит

```
symphony now starts when you log in (<where>); it's running at http://127.0.0.1:7788/
```

Если пользователь сказал, что не хочет запуска при входе, выполните вместо неё `symphony -background -open=false`: она запускает bridge отдельно от терминала и выводит `the symphony bridge runs in the background at http://127.0.0.1:7788/; its log: <data folder>/bridge.log`. Если bridge уже работает, обе команды отвечают `a symphony bridge is already running at http://127.0.0.1:7788/`; это нормально, второй не запускайте.

Проверьте всю цепочку одним запросом:

```bash
curl -s http://127.0.0.1:7788/api/launch/options
```

В ответе есть `"enabled":true` и `"mod":{"ok":true,"id":"symphony-bridge@symphony","version":"0.7.1"}`: bridge работает, нашёл `claude`, а mod установлен там, откуда его загрузят сеансы. При `"enabled":false` поле `mod.code` говорит, что не так, а `mod.fix` — команду, которая это исправит: `mod_not_installed` или `mod_project_scope` (вернитесь к шагу 4), `mod_disabled` (включите его), `mod_check_failed` (`claude plugin list --json` завершилась с ошибкой, так что Claude Code, скорее всего, слишком старый). `"mod":null` означает, что bridge вообще не нашёл `claude` в своём `PATH` (об этом написано в его журнале): добавьте его туда или запустите bridge с `-claude /path/to/claude`.

Журнал bridge — это `bridge.log` в папке данных (`~/.config/symphony` в Linux, `~/Library/Application Support/symphony` в macOS, `%AppData%\symphony` в Windows); если bridge запущен при входе в систему, журнал пишется в `journalctl --user -u symphony` в Linux и в `~/Library/Logs/symphony.log` в macOS.

#### Шаг 6: отчитайтесь пользователю

Откройте офис в браузере (`open http://127.0.0.1:7788/` в macOS, `xdg-open` в Linux, `start` в Windows) и сообщите пользователю:

- Офис находится по адресу `http://127.0.0.1:7788/`. Чтобы нанять первого сотрудника, нажмите «+» на свободном месте и выберите папку: там запустится сеанс Claude Code, внутри bridge, а его окно на странице — это его чат.
- В офисе появляются только сеансы, запущенные со страницы (или вручную с `SYMPHONY_TOKEN`, см. «Запуск сеансов» ниже). Другие сеансы Claude Code пользователя, включая тот, что выполняет эту установку, там не видны.
- Что и куда установлено: путь к программе, mod на уровне пользователя, запускается ли bridge при входе в систему или работает в фоне, все изменения `PATH` и то, что `git` нет, если его нет.
- Как всё это отменить: см. «Удаление» ниже.

Правила: не привязывайте bridge ни к чему, кроме этого компьютера (`-addr` остаётся `127.0.0.1:7788`; входа на странице нет), не запускайте его через `sudo` и не запускайте второй bridge на том же адресе.

#### Обновление

Скачайте новый релиз, как в шаге 2, и замените программу, как в шаге 3; mod обновляется командой `claude plugin update symphony-bridge@symphony` (если маркетплейс — это клон, то вместо этого `git pull` в нём). Работающий bridge использует старую программу, пока не перезапустится: `symphony -autostart off`, затем `symphony -autostart on -open=false` (или остановите и запустите его тем же способом, каким он был запущен). Остановка bridge завершает запущенные им сеансы, поэтому заранее предупредите пользователя. У программы и mod один номер версии; что изменилось в каждом релизе, описано в [CHANGELOG.md](CHANGELOG.md).

#### Удаление

```bash
symphony -autostart off                           # останавливает bridge и его сеансы и больше не запускает его при входе
claude plugin uninstall symphony-bridge@symphony  # mod
claude plugin marketplace remove symphony         # запись маркетплейса
rm ~/.local/bin/symphony                          # программа, куда бы её ни положил шаг 3
```

Папка данных (учётные записи с их token, журнал сообщений, задачи) остаётся; чтобы убрать всё, удалите и её.

## Что умеет

- **Каждый сеанс как чат**: нажмите на сотрудника, и его окно откроется посреди страницы: сверху кто он, ниже сеанс в виде чата: запросы, размышления модели (свёрнуты, оранжевое «Думает…», пока идут), её ответы по мере поступления, вызовы инструментов и сообщения от других сеансов фиолетовым. Напишите внизу, и текст дойдёт до сеанса как ваш запрос; кнопка «Остановить» прерывает его.
- **Подтверждения в браузере**: запросы разрешений (запуск команд, правка файлов) и вопросы AskUserQuestion поднимаются карточками поверх поля ввода в окне этого сотрудника, а красный счётчик в верхней панели ведёт к ним. Если bridge не запущен или не знает учётную запись, сеанс, как обычно, спрашивает в терминале и никогда не зависает.
- **Пиксельный офис**: каждый сеанс — это сотрудник со своим постоянным местом. Зелёный — без дела, жёлтый — работает, красный — ждёт вашего разрешения или ответа, серый — не на работе. Сотрудники без дела сначала сидят на месте в телефоне или играют, потом идут гулять по офису: смотрят телевизор на диване в зоне отдыха, играют в настольный футбол и в догонялки, болтают за круглым столом, наливают кофе, смотрят в окно; со временем уходят вздремнуть, чаще всего прячутся в переговорной. Размер персонажа зависит от модели, а мускулатура — от глубины размышлений. Офис — это один этаж здания большой компании, и он заполняет всё окно: рабочий зал в центре, слева небольшие переговорные на 3–5 человек с табличками, справа переговорная и зона отдыха, а приходят и уходят на лифтах. В панели сверху можно выбрать и размер пикселей, из четырёх: тот же офис, с каждым шагом нарисованный более мелкими пикселями и подробнее.
- **Найти и позвать обратно**: щёлкните по сотруднику без дела — он вернётся на своё место и останется там до своего следующего хода; поле поиска в панели сверху находит сотрудников по имени, имени сеанса или папке (клавиша `/` переводит в него), а щелчок по счётчику рядом с ним (без дела, работают, ожидают, не на работе) выделяет всех сотрудников в этом состоянии. Язычок под панелью убирает её вверх и возвращает обратно.
- **Сообщения между сеансами**: когда сеансы пишут друг другу (SendMessage), через офис пролетает конверт, а сами сообщения сохраняются в журнале сообщений.
- **Запуск сеансов со страницы, без всплывающих окон**: нажмите «+» на свободном месте, чтобы нанять нового сотрудника, и выберите папку, модель, глубину размышлений и режим разрешений (новый сотрудник начинает с «разрешено всё», Opus и максимальной глубиной размышлений); нажмите «За работу» в окне сотрудника, который не на работе, — и он вернётся на своё место. Сеанс работает в собственном терминале внутри bridge, так что ни одно окно не открывается и ничто не забирает фокус; «Открыть терминал» в окне сотрудника показывает этот терминал, когда нужно, а его закрытие ничего не меняет.
- **Команды в переговорных**: нажмите на свободную небольшую переговорную, напишите задачу и выберите от 2 до 5 участников: сотрудников (каждый получает второй сеанс только для этой задачи) или разовых консультантов. По умолчанию первый участник руководит и раздаёт части через SendMessage; каждый участник работает в своём git worktree, в своей ветке, так что никто не лезет в чужие файлы. Пока задача не закончится, участники сидят в переговорной.
- **10 языков**: English, 简体中文, 繁體中文, 日本語, 한국어, Español, Français, Deutsch, Português (Brasil) и Русский. Страница берёт язык браузера, а в панели сверху есть переключатель языка; сообщения bridge следуют `-lang`, иначе языку системы (`LANG` и подобным), иначе выводятся на английском; сообщения mod следуют `SYMPHONY_LANG` (у сеанса, запущенного со страницы, это язык страницы), иначе языку системы, иначе выводятся на английском.
- **Всё локально**: bridge — это одна программа на Go (только стандартная библиотека; сквозные тесты используют ещё chromedp), страницы написаны на чистом JavaScript, и ничего не зависит от сторонних сервисов.

## Требования

- Claude Code 2.1.316 (проверено на этой версии). Для mod нужны function hooks из Claude Code, а это API пока в раннем доступе, поэтому после обновления Claude Code прогоните сквозные тесты.
- Для Linux, macOS и Windows есть готовая программа bridge; Go 1.27 или новее нужен только для сборки из исходников.
- `git` — только для совместных задач: каждый участник задачи работает в git worktree.
- Больше ничего: сеансы, запущенные со страницы, работают внутри bridge на любой платформе.

## Запуск bridge

`symphony` запускает bridge и открывает офис в браузере по адресу <http://127.0.0.1:7788/> (`-open=false` отключает это); <http://127.0.0.1:7788/approve> — упрощённая страница только для подтверждений. Если запустить bridge повторно, пока он уже работает, просто откроется офис. В Windows `symphony.exe`, запущенный двойным щелчком, работает в отдельном окне, а если закрыть это окно, bridge остановится.

| Флаг | По умолчанию | Что делает |
| --- | --- | --- |
| `-addr` | `127.0.0.1:7788` | Адрес, на котором принимать подключения. Входа на странице пока нет, поэтому не привязывайте bridge ни к чему, кроме этого компьютера |
| `-data` | `$SYMPHONY_DATA`, иначе `symphony` в папке настроек | Папка данных: учётные записи с их token (`accounts.json`), журнал сообщений (`messages.json`), задачи (`tasks.json`) и журнал `-background` (`bridge.log`) |
| `-claude` | `claude` | Исполняемый файл claude |
| `-lang` | язык системы, иначе `en` | Язык сообщений bridge (значение по умолчанию задают `SYMPHONY_LANG`, `LC_ALL`, `LC_MESSAGES` или `LANG`) |
| `-mod` | пусто | Для разработки: передавать сеансам mod из этой папки через `--plugin-dir` вместо установленной копии |
| `-web` | пусто | Для разработки: отдавать страницы из этой папки, чтобы правки были видны после перезагрузки |
| `-open` | `true` | Открыть офис в браузере, когда bridge запустится; если на `-addr` bridge уже работает, просто открыть его офис |
| `-autostart` | — | `on`: запускать bridge при каждом входе в систему, с остальными указанными флагами, и запустить его сейчас; `off`: отменить это |
| `-background` | — | Запустить bridge в фоне, отдельно от терминала, с журналом в `bridge.log` в папке данных, и вернуться, когда он ответит |
| `-version` | — | Показать версию и выйти |

**Запуск при входе в систему**: `symphony -autostart on` запускает bridge при каждом входе в систему, с переданными вместе флагами (например, `-addr`), и сразу же запускает его; `symphony -autostart off` отменяет это. В Linux это пользовательская служба systemd (журнал — `journalctl --user -u symphony`), в macOS — агент launchd (журнал в `~/Library/Logs/symphony.log`), в Windows — значение в разделе реестра Run (bridge работает в окне консоли; если его закрыть, bridge остановится до следующего входа). Нужна сама программа symphony, а не `go run`.

**Из исходников**, с Go 1.27 или новее: `git clone https://github.com/feynmanzcys-bytes/symphony.git && cd symphony && go run ./cmd/bridge`.

## Запуск сеансов

**Со страницы**: нажмите «+» на свободном месте, введите имя и выберите папку и параметры. Bridge запускает `claude` в собственном терминале внутри себя: окно не открывается. Окно сотрудника показывает сеанс в виде чата, а его кнопка «Открыть терминал» открывает окно терминала, подключённое к сеансу (`symphony attach <id>` делает то же самое из любого терминала; `Ctrl-]` или закрытие окна отключает, а сеанс продолжается). Сеансы — дочерние процессы bridge: остановка bridge завершает их.

**Из терминала**: создайте учётную запись, чтобы получить token, и запустите с ним `claude`:

```bash
curl -X POST 127.0.0.1:7788/api/accounts -d '{"name":"frontend-alice"}'   # в ответе будет token
SYMPHONY_TOKEN=<token> claude --name frontend-alice --permission-mode manual
```

Рекомендуем режим разрешений `manual`: в режиме `auto` большинство действий выполняется без вопросов, так что до страницы доходит мало запросов. Если bridge работает не на адресе по умолчанию, задайте ещё `SYMPHONY_BRIDGE=http://host:port`. `SYMPHONY_LANG` задаёт язык сообщений mod (иначе язык системы, иначе английский).

Если по адресу bridge на этой машине никто не отвечает, сеанс сам запускает bridge командой `symphony -background -open=false -addr <that address>` (если `symphony` есть в вашем PATH), и bridge продолжает работать после завершения сеанса. Задайте `SYMPHONY_DATA`, если ваши учётные записи лежат не в папке данных по умолчанию.

## Совместные задачи

В небольшой переговорной команда из 2–5 сеансов вместе работает над одной задачей. Для задач нужны `git` и mod версии 0.7.0 (`claude plugin update symphony-bridge@symphony`).

**Как начать задачу**: нажмите на свободную небольшую переговорную и опишите, что нужно сделать. Отметьте участников в нужном порядке (от 2 до числа мест в переговорной), выберите каждому модель и глубину размышлений, а всей команде — режим разрешений (по умолчанию «разрешено всё»), и нажмите «Начать задачу». Участники бывают двух видов:

- **Сотрудник**: получает второй сеанс только для задачи, и этот сеанс работает в папке сотрудника; его собственный сеанс на рабочем месте остаётся как был. Сотрудник участвует только в одной задаче за раз, а у того, кто ещё ни разу не работал, пока нет папки: сначала один раз нажмите для него «За работу».
- **Консультант**: разовый участник, созданный для задачи с обычными полями (имя, папка, модель, глубина размышлений). У него нет рабочего места, он приезжает на лифте и исчезает, когда задача заканчивается.

**Лидер**: по умолчанию первый участник руководит: делит задачу, раздаёт части через SendMessage, проверяет работу, сливает ветки остальных в свою и рассказывает вам, что сделано. Снимите отметку лидера — и каждый получит всю задачу, а распределят её участники между собой. В обоих случаях bridge отправляет каждому участнику первый запрос: кто в команде (участники находят друг друга по имени через SendMessage), ветки каждого и правила.

**Git**: каждый участник работает в своём git worktree, в своей ветке своей папки, `symphony/<task id>/<member>` (например, `symphony/T1/bob`; второй участник с тем же именем получает `-2`), так что никто не лезет в чужие файлы, а ваша собственная рабочая копия остаётся как была. Worktree лежат внутри папки, в `.symphony/worktrees/`, и git их не видит благодаря `.git/info/exclude` (ваш `.gitignore` не трогается). Когда задача заканчивается, всё, что участник не закоммитил, коммитится в его ветку, так что ничего не теряется, а worktree удаляются.

- В ваших собственных репозиториях ничего не сливается: ветки остаются, и сливаете их вы; если есть лидер, в его ветке собрана работа всех.
- Папка, которая не является git-репозиторием, становится им для задачи (`git init` и коммит всего, что в ней лежит) и остаётся им. Когда задача заканчивается, ветки участников сливаются в неё, так что в папке оказывается результат; `.git` и ветки сохраняются.
- Если слияние не удалось, оно отменяется и базовая ветка остаётся такой, как была; ветки остаются вместе с работой на них, а окно задачи показывает, в какой ветке конфликт.

**В офисе**: всю задачу участники сидят за столом в переговорной, а на месте сотрудника тем временем стоит пустой стул. На табличке переговорной виден номер задачи; её огонёк, зелёный, пока переговорная свободна, становится жёлтым, пока идёт задача, и красным, пока кто-то из участников ждёт вашего разрешения или ответа. Нажмите на переговорную, чтобы открыть окно задачи: сама задача, участники с их папками и ветками, чат команды и «Завершить задачу». Щелчок по фигурке участника в переговорной тоже открывает окно задачи; щелчок по участнику в окне задачи открывает его окно чата рядом — такое же, как окно сотрудника, и только для одного участника за раз (щёлкните по другому участнику, чтобы переключиться). Красный счётчик в верхней панели и поле поиска открывают участника задачи так же.

**Чат команды**: в окне задачи видны сообщения, которые участники отправляют друг другу, — у каждого пиксельная фигурка и имя отправителя, а текст начинается с `@` и адресата. Ниже есть поле, чтобы вы сами писали команде: `@bob-T1 …` уйдёт только этому участнику (несколько `@names` — всем им; если набрать `@`, откроется список участников, выбрать можно стрелками, Enter или щелчком), а сообщение без `@` уйдёт всем в задаче. Enter — отправить, Shift+Enter — новая строка.

Задача заканчивается, когда вы завершаете её в окне задачи или когда заканчивается её последний сеанс: bridge останавливает сеансы участников, разбирается с git, как описано выше, и удаляет консультантов. Задача, которая ещё шла, когда bridge остановился, завершается так же при следующем запуске bridge.

## Учётные записи и места

- Учётная запись в symphony — это имя, token и постоянное место. Одна учётная запись обслуживает один сеанс за раз и ещё один в задаче, в которой участвует; любой другой сеанс получит отказ, и его подтверждения останутся в терминале.
- Вход в Claude здесь не настраивается: все сеансы могут работать под одним логином Claude.
- Данные хранятся в `~/.config/symphony` (Linux), `~/Library/Application Support/symphony` (macOS) или `%AppData%\symphony` (Windows), либо там, куда указывает `-data` / `SYMPHONY_DATA`. В `accounts.json` лежат token, и читать его может только владелец (0600); в Windows его защищают права доступа к папке пользователя.

## Безопасность

- Bridge принимает только запросы, адресованные этому компьютеру, и отклоняет запросы на запись, которые другой сайт отправляет через ваш браузер: страница умеет запускать сеансы, а значит, выполнять команды на этом компьютере.
- Входа на странице пока нет, поэтому **не** привязывайте bridge ни к какому адресу, кроме адреса этого компьютера.
- Программы не подписаны. macOS может отказаться открывать копию, скачанную через браузер, потому что не может проверить разработчика: нажмите «Все равно открыть» в разделе «Системные настройки» → «Конфиденциальность и безопасность» или один раз выполните `xattr -d com.apple.quarantine symphony`. Windows SmartScreen тоже может предупредить: нажмите «Подробнее», а затем «Выполнить в любом случае». В `checksums.txt` релиза есть SHA-256 каждого архива.

## Платформы

| Система | Сеансы, запущенные со страницы | «Открыть терминал» | Проверено |
| --- | --- | --- | --- |
| Linux | Псевдотерминал внутри bridge | Графический терминал (x-terminal-emulator, gnome-terminal, konsole, xterm) с `symphony attach` | Полные сквозные тесты |
| macOS | Псевдотерминал внутри bridge | Terminal.app с `symphony attach` | Полные сквозные тесты |
| Windows | Псевдоконсоль (ConPTY) внутри bridge | Новое окно консоли с `symphony attach` | Только кросс-компиляция и модульные тесты |

На вопрос о доверии к папке («trust this folder») bridge отвечает за вас на любой платформе.

## Разработка

```bash
go test -race ./...                         # модульные тесты bridge и переводов
claude plugin test mods/symphony-bridge     # модульные тесты mod
claude plugin validate .                    # проверка маркетплейса
claude plugin validate mods/symphony-bridge  # проверка mod
SYMPHONY_E2E=1 go test -tags e2e -v -count=1 -timeout 20m ./e2e/   # сквозные тесты: запускают настоящие сеансы и тратят токены
```

- Работа над mod: `go run ./cmd/bridge -mod mods/symphony-bridge` — и сеансы, запущенные со страницы, получат вашу копию mod через `--plugin-dir`; в сеансы, которые вы запускаете вручную, добавьте `--plugin-dir mods/symphony-bridge` сами.
- Работа над страницами: `go run ./cmd/bridge -web web` — и правки видны после перезагрузки.
- Чтобы посмотреть на офис без настоящих сеансов, запустите второй bridge и наполните его выдуманной активностью: `go run ./cmd/bridge -addr 127.0.0.1:7799 -data /tmp/demo`, затем `go run ./cmd/demo -base http://127.0.0.1:7799`.
- Переводы: каждый язык — это один файл, `web/locales/<lang>.json` для страниц и `internal/i18n/locales/<lang>.json` для bridge, с теми же ключами, что и в `en.json`; немногие сообщения самого mod лежат в `mods/symphony-bridge/hooks/messages.ts`. Модульные тесты проверяют, что в каждом языке есть все ключи и те же `{placeholders}`, а сквозной тест `TestI18n` открывает страницы на каждом языке.
- Сквозным тестам нужны claude, tmux (для сеансов, которыми тесты управляют сами) и Chromium или Chrome, поэтому они запускаются на Linux и macOS. По умолчанию они берут mod из этого репозитория; чтобы использовать установленный mod, задайте `SYMPHONY_E2E_MOD=installed`. Скриншоты сохраняются в `e2e/artifacts/`.
- Релизы: поднимите версию в `mods/symphony-bridge/.claude-plugin/plugin.json`, добавьте в `CHANGELOG.md` раздел `## vX.Y.Z (date)`, перенесите dev в main, затем поставьте тег на этот коммит в main и отправьте тег (`git tag -a v0.7.0 -m v0.7.0 && git push origin v0.7.0`); GitHub Actions проверит, что тег совпадает с версией в `plugin.json` и что раздел есть, соберёт программу для всех платформ и опубликует релиз, заметки к которому начинаются с этого раздела (`.github/workflows/release.yml`; суффикс вроде `-rc.1` делает пре-релиз). `.github/release.sh v0.7.0 dist` собирает такие же архивы локально.
