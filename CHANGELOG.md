# Changelog

What changed in each release of symphony. The program (the bridge) and the mod share one version number. A release's notes start with its section here: the release workflow stops before building when the section is missing. Releases before v1.0.0 came out before the repository was public; their notes are kept below.

## v1.7.2 (2026-11-04)

Update the program (`brew upgrade symphony`, `scoop update symphony`, or the archive) and the mod with `claude plugin update symphony-bridge@symphony`: this time the mod changed too (a session that types `/clear` carries on). (v1.7.0 and v1.7.1 were tagged with the same code, but their releases were never published: a check in the workflow took braces in these notes for a placeholder it had left, and release tags can't be moved. v1.7.2 is that release.)

- **Coworkers is the one page**: the pixel office is out of the repository (its theme, its tests, its keys; the protocol is at 3). `/t/office/` answers with Coworkers.
- **Groups work like chat groups**: 2 to 20 members; a group has a name (the number shows without one) and its description is optional (without one the members are only introduced to each other, and you hand out the work in the team chat); an employee can be in several groups at once, each with a session of its own; "+ Add members" and the × on a member's card add and remove members while the group runs (one removed stays listed as left and can come back as the same member; the team is told, in the team chat too); a member whose session ended has "Start again"; a group no longer ends by itself when nobody is at it, and the groups a bridge finds running when it starts stay, their members off duty.
- **No git branches unless you ask**: by default every member works in its own folder as it is, the same one as at its desk, so nothing has to be merged later; the dialog's box "A git branch and worktree for each member" turns the old isolation on, and the line beside it says that the worktree and the folder drift apart over a long group and that the branches are merged back only when the group is dissolved. Groups without it need no git. The bridge's API: `POST /api/tasks` takes `name`, `git` and an empty `title`; `POST /api/tasks/<id>/members`, `DELETE /api/tasks/<id>/members/<account>`, `POST /api/tasks/<id>/members/<account>/start`; a Task carries `name`, `git` and each member's `left`; a Message of the bridge's own has `origin: bridge`.
- **A face of one's own**: a shape and a color picked when a coworker is made or on the coworkers page (import and export carry it); the state is a stroke along the face's own outline that glows outward (green and slow idle, amber working, red and quick waiting), no ring around it; livelier eyes.
- **The conversation**: the answers in bubbles again; the messages between coworkers on the left, never on your side; your prompts and your decisions on the asks (a question's answer, a permission allowed or denied with the reason) as bubbles of yours, without a "You" label; a prompt the engine put in by itself (a background task's notification, a scheduled run) as a one-line notice, not a bubble; images into a conversation (the clip, a paste or a drop; kept in the session's folder under `.symphony/inbox/`, so the session reads them without an approval); code blocks highlighted by a parser of symphony's own (go, js/ts, python, rust, c, c++, java, kotlin, swift, c#, sh, console, dockerfile, json, yaml, toml, html, css, sql, diff), and an HTML entity in the model's Markdown shown once.
- **The sidebar**: no state words; each row shows the newest line of its conversation, or, waiting for you, the kind of answer it needs; names shown short everywhere (`grace` for `grace-T1`); the group rows by name.
- **The profile**: its Model row is two drop-downs while the session is online, which switch the running session's model and thinking effort (`POST /api/sessions/<id>/model`, run as `/model` and `/effort` in the session); its small screen is told apart from "Take over".
- **Readable**: the settings have the text size (a zoom of the whole page, the layouts following) and the typeface (the system's, serif, rounded, monospace).
- **The mod (1.7.2)**: a session that types `/clear` (or resumes or forks) carries on under its new id even when the engine says the new session's start before the old one's end; the problem report carries the activity log.
- `TestScreens` exceeds the cap with 21 members; `TestTask` walks through a git group and a plain, named one with a member added, one removed, one started again and the dissolution; unit tests for members coming and going, an employee in two groups, a group outliving its members and a bridge restart.

## v1.2.0 (2026-11-03)

Update both parts, as before: the program, and the mod with `claude plugin update symphony-bridge@symphony`. On Linux and macOS, run `symphony -autostart on` again if symphony starts at login, so the unit or agent gets its new limits, and, from this version, the Claude Code, proxy and certificate variables of the shell you run it in. symphony can now also be installed and updated with Homebrew (macOS, Linux) or Scoop (Windows): the README says how.

- **"Allow for this session"** on a permission's card lets the same kind of call through without asking until the session ends: every file edit, a command by how it starts (`npm test`, `git status`; never a command joined to another), or a tool. The mod proposes the rule with the card and keeps it once you click it; it lets through only what Claude Code would have asked about, never past a deny rule or the organization's settings. The chat says what was allowed for the session.
- **An MCP server's form** (an elicitation) shows on the page as a card, with its fields: it is answered in the session's terminal, which the card opens in the window, and goes once answered. The window says the session needs a form filled in.
- **Coworkers' cards sit in the conversation**, under the line where the ask came up, and the input stays usable for a message that doesn't answer it; with the terminal shown, they rise over it and go back after.
- **"Tell it who else is in the office"** in the launch dialog: the session's system prompt names the others online, with their folders and tasks, once per conversation, so it can reach them with SendMessage (`SYMPHONY_CONTEXT=1`).
- **The terminal in the page**: "Terminal here" in the employee window shows a page-started session's terminal in the window, with its colors, wide characters and scrollback; you type into it as into a terminal (Esc and Tab go to the session), and "Back to chat" or Ctrl+] returns. Coworkers' computer shows it small and live; a click opens it in the conversation.
- **Install with Homebrew or Scoop**: this repository is a Homebrew tap and a Scoop bucket, written from each release's checksums. Every release archive now carries GitHub's attestation of where it was built (`gh attestation verify`), and the archives are reproducible: two builds of a commit give the same checksums.
- **The mod gets the program when it's missing**: when no `symphony` is on PATH as a session starts and no bridge answers, the mod downloads the release of its own version from GitHub (https only, checked against the release's `checksums.txt`) into its own folder and starts it. `SYMPHONY_DOWNLOAD=0` turns this off.
- **The token leaves the session's environment** once the session started, so the commands, scripts and MCP servers it runs don't inherit it; `/reload-plugins` keeps the session in the office, with what was allowed for it and the office text its prompt had.
- **Starting at login** keeps `CLAUDE_CONFIG_DIR`, the proxy variables and the extra certificate authorities as the shell that ran `-autostart on` had them, in `autostart-env.json` in the data folder (readable by you only), so a session started from the page after a reboot finds its settings and gets through the proxy. Nothing else is carried (no API keys, no `NODE_OPTIONS`). A Homebrew install's login entry survives `brew upgrade`.
- **Accessibility**: the windows and dialogs work with the keyboard and screen readers (focus moves in and back, Esc never closes a window whose asks wait, new asks are announced, the pixel office has a keyboard roster); every text meets WCAG 2.1 AA contrast and every state mark 3:1 in every theme and color scheme; every theme works in a window 800 px wide. **Mission Control has a light mode**, following the system's, with a switch.
- **A page whose key changed says so** (after the `key` file was deleted, say) instead of reconnecting in silence, and comes back by itself once the browser is signed in again.
- **Faster pages**: a burst's last chat items no longer wait in the browser for more bytes (48 items now show in 2 s, were 14.5 s); HQ's timeline draws at 60 frames a second with 50 sessions streaming (it made a new date formatter per row); Mission Control redraws a tile's sparkline only when it changed; the task chat adds a message instead of drawing all of them again. The bridge encodes the message log and the ledger outside its lock: with 3,900 messages kept, a change held it 3.4 ms, now 0.5 µs.
- **Opening the office on Windows** goes through the default browser itself (the command Windows has for http addresses), so a Windows that asks which app should open .html files, or opens them in an editor, still shows the office, signed in.
- **No more subagents an employee never ran**: the engine ends the helper that makes its prompt suggestion as a subagent after every turn, and the office counted it, so the Subagents chip crept up and gray mini figures gathered by the desks.
- **The pixel office's activity panel** starts with the bridge's recent lines, so a reload no longer empties it.
- **Collaborative tasks**: a member session that names its task late takes the place of its leftover self from the same process (its end never came), or of one silent for 45 seconds, instead of being refused.
- **Development**: in `-mod` mode the bridge warns when the installed mod is enabled too (sessions load both, and every hook runs twice).
- **A session's end ends what it left running.** On Linux and macOS, what a tool put in the background with `&` outlived the session once its shell exited (init adopted it, so nothing led to it); the bridge now also ends every process whose environment carries the session's launch id, and does the same when the session exits by itself, as Windows already did through the session's job object. On macOS this reaches `node`, Homebrew and other third-party programs but not Apple's own (`sleep`, `bash`, `zsh`, `perl`), whose environment the system hides from `ps -E`; the README says so.
- **The exit notice and a failed start show the screen as it was**, from a small model of the terminal's screen: text that was typed and erased, or redrawn over, is no longer in it, and no bits of escape sequences (`(B`, `78`, `=`) are either.
- **`symphony attach`** draws its detach line below the session's last box instead of into it, empties the window's title, and turns off the color-scheme reports Claude Code turns on (a terminal that supports them could have put `^[[?997;1n` into the shell afterwards). The command the page shows for opening a terminal by hand names the program by its full path when `symphony` isn't on `PATH`. On Windows a killed session shows `exit status -1`, not 4294967295.
- **Collaborative tasks**: a `git worktree add` that fails after it made the worktree and the branch (a global `post-checkout` hook that fails) no longer leaves them behind. The task window says the task ended, until it is closed, instead of just closing. The Chinese and Japanese kickoffs read "任务 T1 的" rather than "任务 T1的".
- **Starting at login**: a bridge that fails for good (its data folder used by another bridge, a damaged `accounts.json`, something else on its address) is no longer restarted forever: 5 tries in a minute on Linux, one a minute on macOS; the README says how to look.
- A second Ctrl-C while the bridge stops (a task's git work, a disk that hangs) kills the sessions and exits at once, with status 1 whichever stop finished first. Two sessions starting the bridge at once over a damaged key file no longer leave one of them taking the bridge for another program.
- **The mod**: the goodbye (`session.end`) goes before the reports still queued, so a backlog doesn't cut it off and a session started by hand doesn't get 409 under its new id after /clear. A prompt from the page can't be lost when the mod's connection drops as the bridge hands it over: items are acknowledged in the next poll. The bridge is started from the mod's own folder, never the session's (where a `symphony.exe` could win over the one on `PATH`).
- **Windows with npm's `claude.cmd`**: an employee name or folder holding one of `% ^ & | < > ! "` would have broken claude's command line through cmd.exe (`--name R`, then a second command); it is refused with a clear error (400 `cmd_unsafe_arg`) instead.
- **Prompts from the page**: several sent while the session is busy now enter the engine's queue at once, as typed in the terminal, instead of one per turn; a prompt sent in a session's first seconds no longer enters twice (two polls out at once both got it: the mod drops a poll of an earlier round and an id already done, and the bridge hands unacknowledged items to one poll per 3 s).
- **The exit notice** shows the last lines the session wrote (the "✻ … for …" line among them), not the input box, its borders or the status line, whole lines up to 400 characters.
- **The command the page shows for a terminal by hand**, on Windows: a path with a space in plain double quotes (no doubled backslashes), with `& ` before a quoted program so it runs as pasted into PowerShell (cmd takes it without the `& `).
- The Terminal.app script a failed "Open terminal" wrote is removed, and the unit tests no longer leave such scripts in the temp folder.
- The end-to-end harness answers the trust prompt as the bridge does (Down until the cursor is on Yes).

## v1.1.1 (2026-11-02)

Update both parts, as for v1.1.0: the program, and the mod with `claude plugin update symphony-bridge@symphony`. The program alone already fixes the tasks for an older mod.

- **Collaborative tasks with real sessions**:
  - A member started in a folder Claude Code hadn't trusted yet (a task's worktrees are always new folders) could end at once. The bridge answered "trust this folder" with Down and Enter as soon as the question showed; Claude Code sometimes missed the Down, or drew the question again with the cursor back on "No, exit", and Enter took that. The bridge now presses Down until the screen shows the cursor on "Yes, I trust this folder", and only then Enter; where the screen doesn't show the cursor, it waits a second before the Down and presses Enter a moment after. This holds for every session started from the page in a new folder.
  - An advisor, or an employee off duty at its desk, often never joined its task. Its session's first report (its name, sent while Claude Code started it) went out before the one that named the task, and the bridge took the session for a desk session: no kickoff, the member "starting…" for good, and the task's mentions and its end when the last member leaves left it out. The mod now sends nothing before the session's start, and the bridge seats such a session in its task as soon as a report names it.
- **Windows**:
  - A bridge started with `-background` (as the mod starts one), or any bridge whose output goes to a file or a pipe, started no session from the page: claude got the bridge's output handles instead of its pseudo console, took itself for `claude --print` and exited. Sessions now always get the pseudo console.
  - "Open terminal" opened a window that closed at once: `symphony attach` found no console on its standard handles there. It now uses the console's own.
  - Ctrl-] didn't detach `symphony attach`: the session's pseudo console asks its host for win32-input-mode, and the attach window then sent Ctrl-] as a sequence. Attach no longer passes that request on.
- `symphony attach` turns off, as it ends, what the session left on in the terminal it ran in (mouse and focus reports, bracketed paste, keyboard modes, the alternate screen), so the shell there gets no stray sequences afterwards.
- **An employee window off duty** shows the last session's chat, as long as the bridge keeps it (10 minutes), in every theme. The notice of a process that exited, with its exit status and the last lines of its screen, was in the chat, but the pixel office, HQ and Mission Control showed "No session yet" (Coworkers already showed it).
- **The last lines of a screen** (a failed start, a process that exited) keep the spaces between words: Claude Code 2.1.316 draws them with moves to a column, which the text dropped ("bypasspermissionson").
- The end-to-end tests show the pages in a light color scheme whatever the machine's: on a Mac in dark mode, TestHQ and TestMessenger failed. Two unit tests that assumed Unix paths failed on Windows.

## v1.1.0 (2026-11-02)

Update both parts: the program, and the mod with `claude plugin update symphony-bridge@symphony`. On Linux, when symphony starts at login, run `symphony -autostart on -open=false` again after updating, so the login service is rewritten (see "Stopping a session" below).

- **`symphony -stop`** stops this data folder's bridge, however it was started (in a terminal, with `-background`, or at login), on every platform: its sessions end and it exits cleanly, and nothing else is touched. As everywhere, it shows the page key only to a bridge that proves it has it. The README's Update and Uninstall steps use it instead of `pkill -x symphony`, which stopped every symphony process at once. A bridge started at login stays stopped until the next login.
- **Security**: the page API no longer answers requests a browser says come from another site or another port of this machine. A link, on a website or in another app (mail, chat, a terminal), could send the browser to an API address with the page key's cookie: the bridge then read a folder the link named (on Windows, a network share, which can hand the user's credentials to it). The folder-listing call now refuses every link, and the rest of the API those from another site or port; the pages, addresses typed in and programs are as before.
- **One bridge per data folder**: a second bridge started on the same data folder (with another `-addr`, or by a session whose `SYMPHONY_BRIDGE` wrote the address another way) took the running bridge's tasks for leftovers and ended them, committing the members' work and removing their worktrees under their running sessions, and the two then wrote over each other's files. The bridge now locks its data folder: a second one says where the first runs, opens its office and stops without touching anything. `-stop` finds the data folder's bridge at whatever address it runs.
- **Data files**: each write reaches the disk before it replaces the file, and a write that fails (a full disk, a read-only folder) is in the log instead of nowhere; making or deleting an employee then fails with a message instead of seeming to work. A damaged message log or ledger (cut short by a crash, say), or an empty task list, is set aside as `<name>.corrupt-<time>` and the bridge starts without it, where it refused to start; a damaged `accounts.json` or `tasks.json` still stops it, now naming the file and what to do. A file that exists but can't be read stops the bridge instead of being taken for empty and overwritten. Task numbers skip the `symphony/T<n>/` branches already in the members' repositories, so a new or reset data folder doesn't collide with earlier tasks' branches.
- **Sessions started from the page**: one whose claude exits (a crash, a lost login) goes off duty at once, with the exit status and the last lines of its screen in its chat, instead of looking busy for 45 seconds and then going gray with no reason. A start that times out (claude stuck at a first-run prompt) ends its process, which used to keep running unseen, unless you are using its terminal; a desk can't be started twice at once (a double click, two pages), which left a hidden second claude that could take the desk later, and "Start work" while the last start's process still runs says so, with the command that opens its terminal. A bridge started by a session's mod no longer passes that session's token on to the sessions it starts (on Windows a new employee could report in as the one that started the bridge).
- **Stopping a session** sends a hangup, waits up to 3 seconds, then ends the session and whatever it started, tool processes in sessions of their own too (a dev server, a watcher), which survived `symphony -stop` and a task's end. On Linux the login service now has `KillMode=mixed`, so stopping it also ends what is left. A bridge running in a terminal stops cleanly when the terminal closes.
- However a session goes off duty (it ends, it stops answering, a new session replaces it, its process exits), its pending approvals and questions are withdrawn, so the red count no longer stays lit for a session that is gone, and the activity log has its end.
- **Tasks**: the bridge's own commits and merges no longer depend on the user's git configuration (hooks, `merge.ff=only`, signing), which made most tasks with two or more members fail at their end. A merge that fails for another reason than a conflict is no longer called a conflict and shows git's own words, and the merges before it are taken back with `git reset --keep`, which keeps uncommitted changes in the folder (it was `--hard`). A task's error lists every failure of its cleanup, not only the first. A folder in a repository git can't read or won't trust is refused instead of being made a repository of its own. What a task that failed to start couldn't undo is in the log.
- **The mod**: after `/clear` (or a `/resume` inside a session) it kept the old session's id and stopped its heartbeat and its inbox, so the employee went off duty while working and the page's messages never arrived; it now carries on as the new session (a task member gets its kickoff again). Heartbeats carry the model, the effort and the rest, so a bridge that restarted shows them again. A message from the page that a hook or the engine refuses shows as not delivered, with the reason. While an approval waits on the page, the terminal says so once; Esc withdraws the card at once, and a bridge that stops answering hands the decision back to the terminal after 25 seconds. When `symphony -background` fails, the message says why. The mod's folder has a README and the license.
- **The pages**: a banner says when the bridge can't be reached, and a call without an answer fails after 15 seconds with that message instead of hanging. A page that fell behind (a frozen or stalled tab) is let go by the bridge and reconnects for the whole state, so it no longer misses approvals and chat lines. A page hidden for 10 seconds lets its connection go, so tabs left open no longer use up the six connections a browser makes to the bridge (with six, clicking Allow hung). A long input in an approval card shows its start and its end, and Allow waits until "Show all" has shown all of it. A task's team chat no longer loses its first messages when the office has many. Rows, tiles and name tags no longer swallow clicks while their session works. An ask card can't be sent twice, or empty. Mission Control's alarm sound plays after a reload once the page is clicked.
- A session keeps its newest 8 finished subagents (the count stays), so a long session's state no longer grows without end. The mod check (`claude plugin list`) no longer fails for 10 seconds when the page that started it closes. On Windows, git and the mod check no longer flash console windows, and the sessions end when the bridge dies in any way.
- Fixed: a session's terminal output with a huge cursor move (an escape sequence it can print, from content it read) crashed the bridge. Such a move now counts as at most 1,000 spaces, and all of them together as at most 64 KiB.
- Fixed: a repository whose current branch is named like an option (`--lock`, say, which git allows and a clone takes from upstream) made a task's worktree come out locked or otherwise wrong; the name is no longer read as an option.
- Terminal sizes past what a terminal holds are ignored, as zero already was.
- An update the bridge couldn't encode for the page (a number that isn't finite) went out empty, which froze the office with nothing in the log. It is now left out, the log says why, an API answer that can't be encoded is a 500 instead of a 200 cut short, and durations and costs no session can mean (negative or absurd) are dropped when the mod reports them.
- The HQ, Coworkers and Mission Control themes now show the members' faces in a task's team chat (a quoting mistake hid them), and Coworkers' profile tooltips no longer show `&amp;` and the like.
- The bridge also stops cleanly on Ctrl-C or SIGTERM when it can't start sessions (no `claude`): what waits to be written is written first.
- README: the install steps now read the page key from wherever the data folder is (`SYMPHONY_DATA`, `XDG_CONFIG_HOME`), quote `claude plugin list --json` as it prints, check the download with whichever of `sha256sum` and `shasum` the system has, say what to do when only the program or only the mod is installed, and say where `-background` prints; `-addr` can be any port on this machine.

- **The office needs a key**: the bridge makes a page key on its first start (`key` in the data folder, readable only by you) and keeps it across restarts. Every page and every call the pages make must show it (the mod still uses the account's token). `symphony` opens the office already signed in: the browser opens `open.html`, a file only you can read that passes the key on, so the key never appears on a command line. The bridge's log prints the office's address with `?key=`. A browser without the key gets a page that says how to get in. `symphony attach` and the demo read the key from the data folder (`-data`).
- **This machine only**: `-addr` must be `127.0.0.1`, `localhost` (which now means `127.0.0.1`) or `::1`, with a port from 1 to 65535; any other address stops the bridge. Connections from other machines are refused. When something else answers at the address (another program, a bridge with another data folder, or an older symphony bridge), symphony says so and stops instead of opening it: it shows the page key only to a bridge that proves it has the key, and so do `symphony attach` and the demo. `-autostart on` turns nothing on when the address is taken.

- **The mod checks the bridge before it sends its token**: it sends a hash of the token and a random value to `POST /api/hello`, and only a bridge that knows the token can answer correctly. It checks again after a lost connection, and before each report while the bridge turns the session away as busy. A new message says when what answers isn't a symphony bridge the session can trust, or is older than the mod. `SYMPHONY_BRIDGE` must be on this machine (http) or use https; anything else gets a message and the bridge is never contacted.
- The mod no longer reads `.claude.json`: the login comes only from Claude Code's `$.session.identity()`, which answers only a mod installed through the organization's managed settings, so for most people the login chip stays empty. It no longer reports the git remote, and the bridge removes user names and passwords from a remote that an older mod sends.
- A malformed answer from the page (a decision other than allow or deny, say) leaves the decision to the terminal.
- Fixed: a chat item could reach the page with text it got later, so the next streamed piece showed twice (a data race). Each push now carries the state of the moment it was made.
- Fixed: at a task's end, the files git ignores in a member's worktree (build output, `.env`, `node_modules` ...) were deleted with the worktree. They are now moved to `.symphony/kept/<member>-<task id>/` in the member's folder (the task's `kept`).
- Fixed: at a task's end, a repository checked out in a member's worktree (a submodule it initialized, or one it made) lost the commits only it had, as the worktree was removed anyway. Now the worktree stays and the task fails, naming that repository.
- The terminal command the bridge gives for a session (`symphony attach <id>`) names `-addr` and `-data` when the bridge doesn't use the defaults.
- Fixed: a plain folder made a repository for a task committed everything in it, secrets included. `.env`, `.env.*`, key files (`*.pem`, `*.key`, `id_rsa*` ...), `.npmrc`, `.netrc`, `.pypirc`, `node_modules/` and `.DS_Store` now go in its exclude list before the first commit: they stay in the folder, out of the repository and the worktrees.
- **New defaults**: a new employee, an advisor and a task start with Claude Code's own settings ("Default") for the model, the thinking effort and the permission mode, instead of Opus, max and `bypassPermissions`; a returning employee keeps its last choices. Picking `bypassPermissions` shows a red line that says what it allows.
- **The pixel office's people are new**: hair, a face, a shirt in one of several colors, trousers and shoes, picked by seat; off duty they are gray. Size still follows the model, muscles the effort, and max effort still wears a red headband. symphony's own mark, two beamed eighth notes, is the logo in the bar, the sign on the back wall and the show on the lounge TV.
- The Messenger theme is now called **Coworkers** (its address stays `/t/messenger/`).
- Docs and community files: the README's install runbook verifies the download's checksum and asks before changes that outlast the install; new sections on cost and permissions and on what the bridge protects; `SECURITY.md` (how to report a vulnerability privately), `CONTRIBUTING.md`; CI runs on pull requests; Dependabot keeps the actions and Go modules up to date. symphony is an independent project, not affiliated with Anthropic; the manifests say so.
